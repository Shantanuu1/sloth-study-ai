# 🦥 Sloth Study

**notes in, flashcards out**

Sloth Study is a local-first AI study assistant. Upload lecture notes (PDF or TXT) and it creates a **summary**, a deck of **interactive flashcards** and a **five-question quiz**. All of it is generated by **Gemma 4 running on your own laptop through Ollama**.

Hackathon category: **Best Use of Gemma 4**

---

## The problem

Students spend hours turning lecture notes into revision material: summaries, flashcards and practice questions. Many skip that step and just reread their notes, which feels productive but works poorly for memory. Research on learning shows that **active recall** (testing yourself) works much better.

Students also don't always want to upload their notes, essays or course material to a cloud service.

## The solution

Sloth Study does the conversion automatically and keeps everything on the student's laptop:

1. **Upload** a PDF or TXT file (or try the built-in demo notes).
2. **Read** a short overview, key points, definitions and takeaways.
3. **Recall** with flip cards: question on the front, answer on the back.
4. **Test** yourself with a five-question multiple-choice quiz, then see your score and an explanation for every answer.

## Features

- Drag-and-drop or click-to-upload for **PDF and TXT**, with a 10 MB limit checked in the browser *and* on the server
- Text extraction from PDFs with `pypdf`, plus friendly messages for scanned, encrypted, corrupted or empty files
- **Summary:** overview, 5–10 key points (depending on note length), definitions and takeaways
- **Flashcards:** about 6–10 cards depending on note length. Click or press Space to flip, use ← / → to move, with a card counter
- **Quiz:** exactly five questions with four options each. Correct answers **stay on the server** until you submit, so you can't peek with developer tools
- Score out of five, a percentage, the correct answers and an explanation for each one
- A live **"Local AI ready"** status that checks Ollama and your model
- **Demo notes** button, clearly labelled as a demo
- Responsive, keyboard-friendly, visible focus states, respects reduced-motion settings
- No external fonts, CDNs or trackers. The page works fully offline

## How Gemma 4 is used

| Step | What happens |
|---|---|
| 1 | Flask extracts and cleans the text, then trims very long notes to `MAX_NOTE_CHARS` (default 12,000 characters) so the prompt fits the context window of a small model. |
| 2 | One request goes to **`POST http://127.0.0.1:11434/api/chat`** with the model from **`OLLAMA_MODEL`**, `stream: false`, `think: false` and a modest `num_ctx` (8,192) to keep RAM use low. |
| 3 | The request passes a **JSON schema** in Ollama's `format` field, so Gemma 4 returns `summary`, `flashcards` and `quiz` in a fixed structure. |
| 4 | The system prompt tells Gemma to treat the notes (wrapped in `<notes>…</notes>`) as **untrusted source material**, never as instructions, and to use only facts that appear in them. `<notes>` tags inside the upload are neutralised so a file can't "break out". |
| 5 | Python **validates** the reply: correct types, four distinct options, an answer index from 0 to 3, exactly five questions, at least three flashcards. If the JSON is malformed, the app **retries once** and then shows a friendly error. |
| 6 | The quiz answer key is kept in server memory. The browser only gets the questions and options until the student submits. |

Generating everything in **one** call (rather than three) means the notes are only processed once, which matters a lot on a CPU-only laptop.

**Local-only guarantees in code** (`check_local_config` in `app.py`):

- `OLLAMA_MODEL` must be set. No model name is hardcoded.
- Model tags containing `cloud` (for example `gemma4:cloud`) are **refused**, because Ollama cloud models run off-device.
- The model must be a Gemma 4 tag.
- `OLLAMA_URL` must point at `127.0.0.1` / `localhost`.

## Architecture

```
 Browser (HTML + CSS + vanilla JS)
   │  POST /api/generate  (multipart file)        GET /api/health
   │  POST /api/quiz/<id>/score  (JSON answers)
   ▼
 Flask app (app.py, bound to 127.0.0.1)
   ├─ validate type + size → extract text (pypdf / UTF-8 / cp1252)
   ├─ clean + trim notes → build prompt (notes marked untrusted)
   ├─ call Ollama /api/chat with JSON schema ──► Gemma 4 (local, via Ollama)
   ├─ parse + validate JSON (retry once)
   └─ keep quiz answer key in memory → score on submit
```

```
sloth-study/

```

## Setup on Windows 11 (step by step)

All commands go in **PowerShell** or the **VS Code terminal** (Terminal → New Terminal), opened inside the `sloth-study` folder.

### 1. Install Python and Ollama

- Python: <https://www.python.org/downloads/windows/>. Tick **"Add Python to PATH"** during installation.
- Ollama: <https://ollama.com/download>. Run the installer, then open **Ollama** from the Start menu.

Check both:

```powershell
python --version
ollama --version
```

### 2. Download a Gemma 4 model

Check the current tags at <https://ollama.com/library/gemma4/tags>. When this project was written, the smallest local tag listed was **`gemma4:e2b-it-qat` (about 4.3 GB)**. Larger tags such as `gemma4:e4b` are likely too heavy for 8 GB of RAM. Never pick a `cloud` tag: the app refuses them.

```powershell
ollama pull gemma4:e2b-it-qat
ollama run gemma4:e2b-it-qat "Explain active recall in three sentences."
ollama list
```

If the model answers, it works on your machine. Note the exact name shown by `ollama list`.

### 3. Install the Python packages

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 4. Configure the model

Either set it for the current PowerShell window:

```powershell
$env:OLLAMA_MODEL = "gemma4:e2b-it-qat"
```

…or copy the settings file once and edit it:

```powershell
Copy-Item .env.example .env
notepad .env
```

### 5. Start Sloth Study

```powershell
.\.venv\Scripts\python.exe app.py
```

Open **<http://127.0.0.1:5000>** in your browser. Keep the terminal open while you use the app.

**Shortcut:** `powershell -ExecutionPolicy Bypass -File .\run.ps1` does steps 3–5 for you.

### 6. Use it

1. Check the status pill in the top-right corner says **Local AI ready**.
2. Drop a PDF or TXT file (try `sample/sample-notes.pdf`), or click **Try the demo notes**.
3. Click **Generate study material** and wait. On an 8 GB laptop this can take a few minutes.
4. Read the **Summary**, flip through the **Flashcards**, then **Submit** the quiz to see your score.
5. Click **Upload another file** to start again.

### 7. Stop it

Press **Ctrl + C** in the terminal. To free the model's memory too, quit Ollama from the system tray (or run `ollama stop gemma4:e2b-it-qat`).

### Run the tests

```powershell
.\.venv\Scripts\python.exe -m pytest
```

The tests cover the home page, unsupported, empty, oversized, corrupted and scanned files, PDF and TXT extraction, malformed and invalid model output, Ollama errors, the local-only checks and quiz scoring. Ollama is mocked, so you don't need the model to run them.

## Troubleshooting

| Problem | Fix |
|---|---|
| `python` is not recognized | Reinstall Python with **Add Python to PATH** ticked, then open a **new** terminal. Or try `py --version`. |
| `ollama` is not recognized | Restart the terminal after installing. Check that Ollama appears in the Start menu. |
| "Ollama isn't running" | Open the Ollama app (llama icon in the system tray), or run `ollama serve` in a separate terminal. |
| "Model … isn't installed" | Run `ollama list`. Either `ollama pull <tag>` or set `OLLAMA_MODEL` to the exact tag listed. |
| "OLLAMA_MODEL is not set" | `$env:OLLAMA_MODEL = "gemma4:e2b-it-qat"` in the **same** terminal, or create `.env`. Then restart `app.py`. |
| "Not enough free memory" / very slow | Close Chrome tabs and other apps. Use the smallest Gemma 4 tag. Lower `OLLAMA_NUM_CTX` to `4096` and `MAX_NOTE_CHARS` to `6000`. |
| "Gemma took longer than … seconds" | Upload a shorter file, or raise `OLLAMA_TIMEOUT` (e.g. `1200`). The first request is slowest because the model has to load. |
| "No selectable text in this PDF" | It's a scanned or image PDF. Export the PDF again from Word or Google Docs, or copy the text into a `.txt` file. OCR isn't supported. |
| "Answer wasn't in the expected format" | Click Generate again. Shorter notes help small models stay on track. |
| Port 5000 already in use | `$env:PORT = "5050"`, then start again and open `http://127.0.0.1:5050`. |
| `run.ps1` cannot be loaded | Use `powershell -ExecutionPolicy Bypass -File .\run.ps1`. |

## Privacy design

- Flask listens on **127.0.0.1 only**, so other devices on your Wi-Fi can't open the app.
- Uploads are read **in memory** and never written to disk or stored after the request.
- Logs record only character counts and timings, **never note content**.
- Notes go only to Ollama at `127.0.0.1:11434`. Cloud model tags and non-local URLs are refused in code.
- All AI text is put on the page with `textContent` (never `innerHTML`), so model output can't inject HTML or scripts.
- Errors are shown as friendly messages. Python tracebacks never reach the browser.
- No external scripts, fonts or analytics are loaded.

Ollama itself is a separate program. Keep it on its default local-only setting: don't set `OLLAMA_HOST=0.0.0.0` or expose port 11434 to the internet.

## Known limitations

- **No OCR.** Scanned or photographed PDFs are rejected with an explanation.
- **Long notes are trimmed** to the first ~12,000 characters (configurable) so a small model can handle them. The page tells you when this happens.
- **Speed depends on your hardware.** On a CPU-only 8 GB laptop, one generation can take several minutes.
- **Small models make mistakes.** The prompt tells Gemma to use only the notes, but check important facts yourself.
- Quizzes live in server memory, so restarting `app.py` expires any open quiz. Generate again to get a new one.
- The app is single-user and meant to run on your own computer. It isn't a hosted multi-user service.

## About "deployment"

Sloth Study is meant to run **on the student's own computer**. That's the privacy point. Hosting it on a public server would mean running Gemma 4 on that server and sending students' notes to it, which this project deliberately avoids. The GitHub repository is the deliverable: anyone can clone it, install Ollama and run it locally in a few minutes. GitHub Actions runs the test suite on every push (`.github/workflows/tests.yml`).

## Demo script (short)

1. Show the **Local AI ready · gemma4:…** pill and point out that the Wi-Fi could be off.
2. Drop in `sample/sample-notes.pdf` and click **Generate**. Explain that the PDF is read in memory and sent only to Ollama on this laptop.
3. Walk through the summary, then flip two or three flashcards with the keyboard.
4. Answer the quiz, getting one wrong on purpose. Submit and show the score and explanations.
5. Upload a scanned PDF or a `.docx` file to show the friendly error.

The full pitch, 2-minute demo script, likely judge questions and submission checklist are in [docs/HACKATHON.md](docs/HACKATHON.md).
