# Sloth Study: hackathon materials

## 60-second pitch

> Hi everyone! We built **Sloth Study**: *notes in, flashcards out.*
>
> Students spend hours turning lecture notes into revision material, or they skip that step and just reread, which is one of the least effective ways to study. What actually works is **active recall**: testing yourself.
>
> Sloth Study does the conversion for you. Upload a PDF or text file of your notes, and **Gemma 4, running locally through Ollama**, writes a summary, a deck of flashcards and a five-question quiz based only on your notes.
>
> The key word is *locally*. The notes never leave the laptop: no cloud AI, no account, no database. We even block Ollama's cloud models in code, so private course material stays private.
>
> We use Gemma 4 with a strict JSON schema, treat the notes as untrusted input, validate every answer on the server, and keep the quiz answers hidden until you submit.
>
> Sloth Study: slow and steady, and you remember more.

## 2-minute live demo script

**Before you start:** Ollama is open, the model has been warmed up once (run a generation before going on stage), `app.py` is running, and the browser is at `http://127.0.0.1:5000`.

| Time | Do | Say |
|---|---|---|
| 0:00 | Show the home page. | "This is Sloth Study. The pill in the corner shows Gemma 4 is installed and running on this laptop through Ollama." |
| 0:15 | Drag `sample/sample-notes.pdf` onto the upload area and click **Generate study material**. | "I'm uploading lecture notes as a PDF. The text is extracted in memory and sent only to Ollama on this machine. Nothing is saved and nothing goes to the cloud." |
| 0:25 | While it loads: | "Gemma gets the notes marked as untrusted source material and has to answer in a fixed JSON schema. Our Python backend validates that structure before anything is shown." |
| When ready | Results appear on **Summary**. (Time this on your laptop beforehand. It depends on your hardware.) | "Here's an overview, the key points, the definitions and the takeaways, all taken from the notes." |
| 1:05 | Go to **Flashcards**. Press Space to flip, → for the next card. | "Flashcards for active recall. They work with the mouse or the keyboard." |
| 1:25 | Go to **Quiz**. Answer all five questions, getting one wrong on purpose, and submit. | "Five questions. The correct answers stay on the server until I submit, so I can't cheat." |
| 1:40 | Show the score and explanations. | "Four out of five, with an explanation for every question." |
| 1:50 | Optional: upload a `.docx` or a scanned PDF. | "Unsupported or scanned files get a friendly error, never a crash." |
| 2:00 | Close. | "Notes in, flashcards out, all on your own laptop. Thank you!" |

**Backup plan:** If generation is slow on stage, keep talking through the architecture slide or the README while it runs. Don't switch to a cloud model.

## Five likely judge questions

1. **How is Gemma 4 actually used?**
   Every summary, flashcard and quiz question comes from one call to Ollama's local `/api/chat` endpoint, using the Gemma 4 tag set in `OLLAMA_MODEL`. We pass a JSON schema in the `format` field so Gemma returns structured data. The backend validates it and retries once if the JSON is broken.

2. **How do you know it's really local?**
   Flask listens only on 127.0.0.1. The code refuses any model tag containing "cloud" and any Ollama URL that isn't localhost. The app loads no external scripts or fonts. You can turn the Wi-Fi off during the demo and it still works.

3. **What stops the AI from making things up?**
   The prompt tells Gemma to use only the notes and to return an empty list when the notes have no definitions. We validate the structure of every answer. Small models can still make mistakes, so we tell students to check important facts against their notes.

4. **What about prompt injection in uploaded files?**
   The notes are wrapped in `<notes>` tags and the system prompt says to treat them as data, not instructions. Any `<notes>` tags inside the upload are neutralised. The model only returns data that we validate. It can't run code or reach anything else, and its output is shown with `textContent`, so it can't inject HTML.

5. **What would you build next?**
   OCR for scanned PDFs, spaced-repetition scheduling for the flashcards, splitting long textbooks into chapters, and exporting decks to Anki. We kept the first version small so the core flow works reliably.

## Final testing checklist

- [ ] `ollama list` shows the Gemma 4 tag you set in `OLLAMA_MODEL`
- [ ] The website opens at http://127.0.0.1:5000 with no errors in the terminal
- [ ] The status pill says **Local AI ready**
- [ ] PDF upload works (`sample/sample-notes.pdf`)
- [ ] TXT upload works (`sample/sample-notes.txt`)
- [ ] The summary is generated by local Gemma 4 (the credit line under the results names the model)
- [ ] Flashcards flip with a click and with Space, and ← / → move between cards
- [ ] The quiz has exactly five questions, and the score and percentage are correct
- [ ] Unsupported, empty and scanned files show friendly errors
